## 八、图片尺寸：不给 `width` 会被裁切（2026-09-28 实测，最易漏的一项）

`image_handler.embed_image` 的宽度决策是：

```python
width_attr → width_cm = px / 37.795            # 96dpi 换算
natural_width_cm = 像素宽 / PNG 内嵌 dpi × 2.54 # 读 img.info['dpi']
final_width_cm = min(有则 width_cm 否则 natural, max_width_cm)
```

- **不给 `width` 时按 PNG 自带的 dpi 还原物理尺寸**。matplotlib 存出的图常带
  100–170 dpi，一张 1400px 的图会被还原成 **25.4 cm**（1400/140×2.54），而 A4 加
  2cm 页边只有 **17 cm** 可用 → 图片右侧被**静默裁掉**，`warnings` 依然是 `[]`。
  本次 8 张图全部中招（实测 22.86 / 25.40 / 30.48 cm 三档）。
- **正确做法**：给每个 `<img>` 显式 `width="600"`（600/37.795 ≈ 15.87 cm，再与
  `max_width_cm` 取小）。本次改为 600 后 8 张图全部落到 13.97 cm，版面内不裁切。
- **验收必须量尺寸，不能只看渲染**：
  ```python
  EMU = 360000.0  # 1cm
  re.findall(r'<wp:extent cx="(\d+)" cy="(\d+)"', document_xml)  # 除以 EMU 得 cm
  ```
  判据：每张图宽 ≤ 可用页宽（A4 竖排 2cm 边距 → ≤17cm）。
- 图注（`<figcaption>`）会被排到图片最后一行右侧再折行，属引擎的排版行为，
  不影响内容；要完全避免就把图注写成图片后面的独立 `<p>`（会多占约 0.2 行高）。
