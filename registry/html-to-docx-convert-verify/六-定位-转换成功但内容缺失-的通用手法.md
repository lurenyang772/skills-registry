## 六、定位「转换成功但内容缺失」的通用手法

引擎的阶段是有序的，用「逐阶段计数」二分定位比读源码快：

1. 把 `_run_pipeline` 的 Phase 0→2 各步（`css_resolve` / `inject_styles` / `split_cjk_latin` / `prepare_fields` / `_extract_special_regions` / `mark_section_boundaries` / `_strip_inter_block_whitespace`）在脚本里手动串一遍，每步后统计哨兵字符串（`__SEC_BOUNDARY__` / `__SPECIAL_REGION__`）的出现次数。
2. 找到数量掉到 0 的那一步，即为丢失点。
3. 需要看运行时中间量时，`monkeypatch` 模块级函数（如 `html_to_docx.section_model.apply_sections`）——converter 是在**函数体内** `from .section_model import ...`，因此运行前打补丁即生效。

> 注意：`__SEC_BOUNDARY__` 是**大写**哨兵，但比对前代码会 `casefold()`。自己写检查时别用大写去 `in txt.casefold()`，会恒为 False（本机曾因此误判「marker 全丢」）。
