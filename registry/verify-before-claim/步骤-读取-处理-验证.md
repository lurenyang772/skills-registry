## 步骤（读取 → 处理 → 验证）

1. **定格声明**——把要说的话写成**一句可证伪的断言**：「节点 n1 的 `conf` 已含 `timeout=30`」。
2. **检锚**——对象标识 ＋ 范围枚举 ＋ 读取时刻，缺任一**即落「无法判定」**，不进后续步骤：
   `grep -n "timeout" /srv/app/conf`（先确认这个对象真的读得到）。
3. **定位形态**——查上表取对应判据库：本机侧 `references/判据库-本机与工具链.md`、远端侧 `references/判据库-远端与接口.md`。
4. **跑阴性对照**——先证明检查器**能**报 FAIL，再谈通过：
   `grep -c "MUST_NOT_EXIST" /srv/app/conf`（期望输出 0 ⇒ 报 FAIL 即对照成立）。
   对照不过 ⇒ 停工修检查器，**不许跳过**。
5. **跑真检**——对照通过才采信 PASS，保留原始输出片段。多通道按**少数否决**聚合
   （任一 FAIL 即降级）、按**通道独立性**排除同源；分歧未归因 ⇒ 落「无法判定」。
6. **收口**——按**三态**给结论；要交付 / 留档的落成**证据包**，交前复跑一次：
   `python3 scripts/evidence_pack.py init --claim "n1 的 conf 已含 timeout=30" --objective conf --scope n1 --out pack.json`
