## 写作规范（强约束）

- 个人观点底稿，非机构正式研报，不构成投资建议；**不得出现任何机构品牌要素**；页脚注明。
- 全中文；引用一手英文资料给英文原文 + 中文简短括注。
- **禁用【】「」《》，一律改用引号**；禁 AI 痕迹与标签词（颠覆性／里程碑／标志性）；禁问答式与内容目录。
- 叙事化深度研究，不做模板化研报句式（禁"投资要点／风险提示／分析师页"）。
- HTML 头部必须有 `ver-banner`（版本号 + 生成时刻）。
- **`_iter_meta.json` 同属「中文 JSON 总结」，同样适用「禁机构名 + 禁全角括号」红线**（v34 补做）：历史 `vN_zh` 条目里可能残留早年写入的机构名与「」『』《》。清理流程（已实跑，可复用）：① 先 `shutil.copy2` 备份并记 sha256；② **替换表按「长串在前」排序**（否则 `JPMorgan` 会被 `Morgan` 之类的短串先命中而残留）；③ 顺序 = 机构长串 → 机构短串 → 全角括号→中文引号；④ 写后回读，扫描 `MS / Citi / Goldman / JPM / 高盛 / 摩根 / 花旗 / 汇丰 / 瑞穗 / 野村 / 瑞银 / 三菱 / 三井住友 / 中信 / 中金` 等 token **必须全部为 0**；⑤ **例外：`Reg NMS` 是法规名不是机构，必须保留**——缩写类 token 逐个看上下文，不得盲替；⑥ 断言用 `len()`/`count()` 直接算，不手写常量；⑦ 残留分两轮清（第一轮后若仍有 token，第二轮定向修，属内容修订不属「断言失败重跑」）。
