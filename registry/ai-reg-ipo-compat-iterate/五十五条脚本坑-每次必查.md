## 五十五条脚本坑（每次必查）

> **标题里的"二十四条"／"五十二条"都是早年版的遗留标签，实际条数见下方编号（现至 55）。编号内部顺序有重号与乱序（例：44 在 41 之前），检索一律按编号或主题词，不按出现顺序。**

1. **长 HTML 禁止单次 Write**。
2. **脚本在写盘之后再 `sys.exit(1)` 时，已成功的替换已经落盘，禁止重跑**——写一个「只处理失败项」的后继脚本（v18 实例：c → d 补锚点 → e 清括号与补姓名）。
3. **版本号同步校验是六处**：VER 变量／头部 ver-banner／末章标题（附录 B）／**页脚 `p.footline` 的「· v{n} 生成于 …」**／**`header.top > div.meta` 里两个版本药丸（`<span class="pill">v{n} · 时间</span>` 与 `<span class="pill">下一版 ≤ 时间</span>`）**／meta 区的「演化重点」与「增量事实」药丸。v22 靠生成器的 `header-pill` 断言才发现 HTML 侧 meta 药丸仍停在 v21。**做法：meta 区的四个药丸按前缀（`演化重点：`、`v20→v21 增量事实`）切片整段替换，比逐字符改稳。**
4. **结构性大块用 slice 替换**：下一版计划整节、附录 A 的新条目、附录 B 的新段落，一律用「起点标题 + 其后第一个 `</section>`」切片整体换掉，一次即成；只有 `evo-table` 行更新与带 span 的 `h4` 才逐条写锚点，且必须先 `print(repr(...))` 取原文。
5. **落盘后按 `<section` 切块逐块比对 `<div` 与 `</div>` 数量**（只比全文件总数会掩盖"一多一少"），并扫描 `【】「」《》『』` 必须为 0。
6. **禁用括号会在新写的句子里复发**——交付前扫描必须覆盖本版新写入的内容。
7. **元数据脚本写后回读的 assert 期望值禁止手写常量**，一律用 `len(追加列表)`；断言失败不得重跑，改为直接读回校验。
8. **窗口外漏登与漏登纪律**：事件早于上一版时点而上一版未收录者，按「漏登补齐」处理并标明真实发生时间，不冒充窗口内增量。
9. **带 `<span class="tag …">` 的 `h4` 标题，锚点只能用「编号 + 空格」**（如 `<h4>㊵ `）——`㊵ v11 新增` 会失配，因为 `v11 新增` 在 span 里。v21 一次失配三条（㊵／㊹／57），改前缀即命中；仍按铁律**不重跑 c**，另写 `_build_v21d.py` 只补失配项。**新批判点的插入点**则取「上一个批判点之后第一个 `</section>` 的下标」。
10. **标签平衡不能只查 `<div>`**：v21 查出两处历史遗留的 `<b>` 失衡——一处是 `</b\n>`（标签内嵌了换行，`s.count('</b>')` 查不到，要用 `re.findall(r'</b\s+>')`），一处是嵌套块里外层 `<b>` 从未闭合。校验脚本要用**栈式顺序扫描**（同时跟踪 `<b>` 与 `</b>` 的进出），只比总数会漏掉「一多一少」。
11. **汇总表与信号表是活交付物**：新增批判点后必须同步补 `table.board.evo-table` 的行（否则 docx 里出现「表格 76 行 vs 正文 75 条」对不上），并把表头里的版本标记（如「本版演化（v18 → v19）」）一起改掉。
12. **构建分五到六段（a–f）**：a＝版本号与标题与表头与页脚；b＝事实骨架增量；c＝新增批判点；d＝第四/五/六/七节；e＝下一版计划与附录 A/B；f＝meta 药丸修正。每段跑完立刻 `print(FAILS)`，全 `[]` 才继续。收尾再跑一次 `_check_v{n}.py`（编号齐全／括号为 0／逐块 div 平衡／`<b>` 栈平衡／版本十处一致）。
13. **`</section>` 不是安全的切片终点（v24 实例，**最严重的一次**）**：演化概览与「一、需要先厘清的『目标命题』」**共用同一个 `<section class="card">`** —— 演化概览 h2 之后没有 `</section>`，直到第一节结束才有。用「起点 h2 → 其后第一个 `</section>`」做 slice_rep，会把**整节 37.9k 字符的第一节内容静默删掉**（411,184 → 379,547 字符），而 div 逐块平衡**照样通过**。**正解**：用下一节真实存在的标题（`<h2>一、需要先厘清`）当终点并把该标题一起写回。**强制兜底：每次落盘后立刻 `print` 一份 h2 列表 + 文件总长度，与上一版逐行比对**，只此一招能在写盘后立刻发现整节丢失。
14. **表格行更新用「标签文本定位 + 单元格切分」，不要写整行正则（v24 实例）**：演化表 **51–65 行的首列被 `<span style="…">` 包裹**、66 行起是裸文本，`<tr><td>51 ` 一律失配；同时支持侧／反驳侧单元格内也含 `<span>`，`[^<]*` 类正则全线失效。**正解**：`s.find('<标签文本>')` → `s.rfind('<tr>')` 取行起点、`s.find('</tr>')` 取终点 → `re.split(r'(</?td>)', row)` 切单元格 → 直接替换第 4 格再拼回。写这一条同时消掉了 skill 原有的坑 9（带 `<span>` 的 `h4` 锚点失配）在表格场景的复发。
15. **`</table></div>` 在本文档出现两次**（演化表与第六节信号表），追加表格行必须**定位第一个的下标后定向插入**，不能用唯一性替换（`count=2` 会直接判失配）。同理 `<title>` 从 v21 起就没同步过——**版本同步校验点现为十处，`<title>` 必须纳入**。
16. **同一张表里两种首列写法并存，"通配"兜底同样会漏（v25 实例）**：演化表 51–65 行是 `<td><span style="color:#7c3aed;font-weight:600">62 …`，66 行起是裸 `<td>66 …`。v25 用 `<td>[^<]*62 ` 与 `re.finditer(r'<td>[^<]*' + n + r' ')` 两种通配都**失配**（因为 `<` 紧接着就是 `span`），而同一次循环里 `<td>63 ` 却命中。**可靠做法：对 51–65 直接写完整前缀 `<td><span style="color:#7c3aed;font-weight:600">{n} `，并在同一脚本里对两种写法各试一次、把结果打进 FAILS。**
17. **新增批判点后必须同步第三节导语条数（v25 实例）**：第三节导语首句是「v{n} 在 v{n-1} 的 X 条之上再添 N 条（…）」，只改 h2 计数与表格行、不改这句，正文导语就会与实际条数矛盾。做法：把 `v{n-1} 在 v{n-2} 的 …` 整体作为锚点，前面插入本版新句、后面原样写回。
18. **禁用括号扫描必须跑两次（v25 实例）**：v25 在 ver-banner 与新增段落里写出 40 处 `「」`（构建时校验通过是因为该次扫描在 a–c 段之后、而 `「」` 出现在 b/c 段写入的文本里），落盘前与 present 前各扫一次，并把 `【】「」《》『』` 六个字符一起扫。
19. **`_gen_word_v{n}.py` 的派生方式固定为"整体复制上一版 + 替换 10 个常量"**：VER／VER_BANNER／VER_BANNER_ALT／VER_LAST_H2／VER_PLAN_H2／SRC／OUT／footline 断言串／`critical-points-{n}` 断言的数字／docstring 首行。逐项 `count==1` 校验后再写盘，写完直接跑（脚本自带 6 条版本同步断言，会先失败再生成）。
20. **事实骨架的增量段插在 `<div class="timeline">` 之前**，不要追加到时间线末尾——该时间线是逆序排列，追加到末尾会打乱时序。
21. **批判点编号是两套符号，自检脚本必须分两段查（v26 实例）**：①–㊿（1–50）写成圈号，51 起写成阿拉伯数字。用 `<h4>(?:<span[^>]*>)?(\d+)[\s、]` 一条正则只能查到 51–98（48 个），会把 1–50 全部误报成缺号、误判为本版丢失了 50 条。正确写法：圈号段用 `'<h4>' + ch` 对 `'①②③…⑳㉑…㊿'` 逐字符比对；阿拉伯段单独查 51–N 的连续性。
22. **禁用括号要在写作时就自检，书名号是最高发的复发形态（v26 实例）**：v26 的事实骨架增量段用了《刑法》与《外国情报监视法》共 4 对 8 个字符，构建时未扫到（扫描跑在 a–c 段之后、而这段文本由 b 段写入），落盘后才发现，只能另写 `_build_v26i.py` 修正。**引用法律名是最容易写出书名号的场景——法律名一律改用引号包裹**；另外 `_v26_util.rep()` 这类「失败只记录不抛异常」的工具会把失败静默带过，**每段脚本必须以 `sys.exit(1 if FAILS else 0)` 收尾并在终端确认 0 FAIL**。
23. **`<b>` 栈平衡校验必须与上一版基线比对，不能拿绝对值当闸门（v27 实例）**：`_check_v27.py` 最初按 `underflow != 0` 判失败，得到 214 并误报为 v27 缺陷；实际 v26 与 v27 的 opens/closes 差**都是 214、residual 都是 0**（历史遗留的开合错序，自早期版本就有）。正解是**同一次运行里同时扫上一版与当前版**，断言 `(opens_delta == closes_delta) and (underflow == 上一版)`；净变化相等即通过，并把「历史遗留」与「本版新增」分开打印。同类教训：**任何"总数相等即通过"的校验，都必须先确认基线是否本来就相等**。
24. **附录 A 与附录 B 之间的 section 分隔存在两种写法（v27 实例）**：附录 B 前的 `<section class="card">` 之后**没有空行**直接接 `<h2>附录 B…`（其他节都是 `</section>\n\n<section class="card">\n\n<h2>`）。因此 `\n</section>\n\n<section class="card">\n\n<h2>附录 B` 这类锚点必然 `count=0`。写作锚点前**先 `print(repr(s[i-400:i+80]))` 取原文**；v27f 因此失配一项，按铁律不重跑、另写 `_build_v27g.py` 定向补齐即通过。
25. **事实骨架增量段的编号是逐版向前累加的，不是固定套数**：v24 为 ①–⑧、v25 为 ①–⑯、v26 为 ①–⑯、**v27 为 ①–⑱**，末尾各跟一条当版新增的检索口径纪律；插入点始终在 `<div class="timeline">` 之前（该时间线逆序排列，追加到末尾会打乱时序）。**不要为了凑数把窗口外的旧事写进增量段**——凡事件早于上一版时点者一律按「漏登补齐」处理并标明真实发生时间。


26. **演化表的表头锚点带 `<th>` 包裹（v28 实例）**：`<b>本版演化（v26 → v27）</b>` 这种写法在正文里**不存在**——真实位置是 `<th>本版演化（v26 → v27）</th><th>v26 备注</th>`。以 `<b>…</b>` 作锚点必然 `count=0`。**正解：整段 `<th>本版演化（v{上一版} → v{本版}）</th><th>v{上一版} 备注</th>` 一次替换，两列一起改**（只改演化列会留下过期的备注列名）。v28a 因此失配一项，按铁律不重跑、另写 `_build_v28a2.py` 定向补齐。
27. **附录 A 的条目格式自 v20 起换过（v28 实例）**：v1–v19 用 `<div class="entry"><time>…</time>…</div>`（共 19 条），v20 起改成 `</div>
<div class="box">
<h4>v{n}（时间）· X 条 → Y 条</h4>…`。**用 `class="entry"` 计数只会数到 19 条，会误判「日志缺行」**。追加新条目应定位**附录 A 内最后一个 `<div class="box">` 的收尾 `</div>`**，把新 box 插在它之后、`</section>` 之前；校验时同时打印 `class="entry"` 数与 `v{本版}（` 串数。
28. **`slice_rep` 的起点标记会被原样保留（v28 实例）**：把 `<div class="ver-banner"><span><span class="v-pill">v27</span>` 当起点会导致新 banner 里仍留 v27。**正解：起点取到不含版本号的那一层**（如 `<div class="ver-banner">`），把版本号写进 new_middle。同类的 `<div class="meta">` 起点也必须只到 `div` 层，四个药丸整段重写后再拼回 `<机构>…` 那一颗。

29. **`slice_rep` 的起点若带药丸标签文字、而 `new_middle` 又重复同一前缀，会产生嵌套 `<span class="pill">`（v29 实例）**：v29a 以 `<span class="pill">演化重点：` 作起点替换 meta 长药丸，而 META_NEW 本身又以 `<span class="pill">演化重点：本版（v29）…` 开头，结果 HTML 里出现 `演化重点：<span class="pill">演化重点：本版（v29）` ——**`<div>` 逐块平衡、`<b>` 栈平衡、禁用括号扫描、版本同步 17 处全部照样通过**（因为最外层 `<span>` 与最内层 `</span>` 数量仍然配平），只有在**生成 docx 之后**才显形为 `演化重点：演化重点：`。**正解：meta 长药丸整段替换时，起点只取到 `<span class="pill">` 这一层（不带后面的药丸标签文字），并把标签文字写进 new_middle；同时把 `<span`/`</span>` 计数纳入自检脚本**（v29 实测 581/581 后才通过）。教训推广：**任何"成对标签总数相等即通过"的校验，都必须先确认它们没有被嵌套错层**——`<div>` 与 `<b>` 都查过之后，`<span>` 是第三个盲区。

30. **一手检索结果必须把检索参数与命中构成一起写进正文与附录（v29 首次执行）**：v29 直查注册声明数据库时，只写"命中 5 条、无一条发行人是当事公司"是不可复现的。正解是三项都写明——**全文本关键词 + 表单类型限定 + 期间**，并把 5 条命中的发行人逐一列出（v29 因此拿到一条此前没有的读数：唯一带实质内容的一条属于当事公司的数据中心交易对手，即"关于它的义务先出现在别人的招股书里"）。参数写进正文的附带收益是：**"逾期未现"从一条二手转述升级为一次可重跑的核对**，且下一版可以把同一参数原样重跑做逐次比对。同理，凡以外部日历或指引日倒推合规截止日时，**必须把输入逐项标为"可核项"或"惯例项"**，只有可核项能推出硬信息。

31. **锚点里的"换行 vs 空格"是最容易失配的一类（v30 实例）**：`</h2> <p class="lead"…`（空格）与文件实际的 `</h2>
<p class="lead"…`（换行）不同，`_build_v30d.py` 一次三处 `count=0`。按铁律**不重跑**，另写 `_build_v30d2.py` 定向补齐即通过。**做法：凡以"上一标签 + 下一标签"为锚点时，先用 `print(repr(s[i:i+400]))` 取原文再写；不要靠记忆拼空格。**
32. **`<b>` 未闭合只有"栈式扫描 + 与上一版净变化比对"能查出来（v30 实例）**：v30a 演化概览的 chart-row 里开了一个 `<b>` 没关，而 `div` 逐块平衡（10 节全过）、`<span>` 596/596、禁用括号扫描、版本同步 15 处**全部照样通过**；只有栈式顺序扫描报 dopen=129 / dclose=128。**校验脚本必须同时保留三种扫描：div 逐块、`<span>` 计数、`<b>` 栈式＋净变化；只比总数会漏掉"一多一少"，只查 div／span 会漏掉 `<b>`。** 同时注意基线并非恒定——v26/v27 的 `<b>` underflow 是 214（历史遗留），v29 是 0；**每次都要与上一版同场比对，不要硬编码 0**。
33. **引用外国法律／法案名称时书名号高发（v30 实例）**：本次在事实骨架里写出 `《数字注意义务》`，构建期未扫到，只能另写 `_build_v30f.py` 修正。**引法律名一律用引号**；并坚持"落盘后与 present 前各扫一次 `【】「」《》『』`"。

34. **某段脚本一旦落盘，就不能在原地改字后重跑（v31 实例）**：v31b 已成功落盘，随后发现增量段的 ⑦ 与 ⑫ 两条需要按"上一版已登记、本版只补新增项"的纪律改写。若重跑 v31b，`ins_before` 的锚点 `<div class="timeline">` 仍然唯一命中，会把整段增量**再插一次**（而 div／span／`<b>`／版本同步四项校验全部照样通过，因为只是内容重复）。**正解：另写 `_build_v31b2.py`，用「旧句 → 新句」的精确替换只改那两句。** 推广：**任何用「唯一锚点 + 插入」写成的脚本都是不可重入的**；要改已落盘的内容，一律改用「旧串→新串」替换式后继脚本，并在脚本名上加 `2`／`fix` 后缀以自我提示。

35. **`「」` 在长句里仍会复发，且只在落盘后才被发现（v31 实例）**：v31c 新增的 121 里写出 `不得把两条上限合并成「最高 7%」`，构建期无报错（该段脚本内的括号扫描并不存在），落盘后跑 `_check_v31.py` 才发现一对 `「」`。**正解：① 写作长句时对"引用式强调"一律用中文引号 `“”`，不用 `「」`；② 每段脚本自身也在 `save()` 之前对 `s` 做一次 `【】「」《》『』` 计数并打进 `FAILS`**，不要只依赖收尾的 `_check_v{n}.py`。

36. **h2／h3 里的计数类标题存在跨版本滞后，必须纳入同步校验（v31 实例）**：v31 构建时发现第五节六条情景的 h3 标题**仍停在 `（v27 33% → v28 32%）` 这一代**——v29、v30 两版都只改了节导语里的概率叙述，没有回填 h3 标题，形成"导语是 v30 的数、标题是 v28 的数"的呈现层矛盾。**做法：把下列全部纳入 `_check_v{n}.py` 的同步清单——`<h2>` 的节标题计数（第三／第四节）、`<h3>` 的子桌面数与**情景概率标题**、`<h3>` 的"134 张子桌面"、版本药丸总数；一旦发现滞后，在本版一并补正并在附录 A 写清"本版修正"。**

37. **一手检索端点可以直接复现（v31 实例）**：注册声明系的核对不必依赖聚合站。`https://efts.sec.gov/LATEST/search-index` 可用 `q=`（全文本短语）＋`forms=`／`root_forms=`（表单类型）＋`startdt`／`enddt`（期间）直连，返回 JSON 含 `hits.hits[]._source` 的 `display_names`／`ciks`／`file_date`／`form`／`file_num`／`adsh`／`biz_locations`／`sics` 与 `hits.total.value`。**把参数与命中构成一并写进正文与附录后，"逾期未现"就升级为可逐次复跑的序列**；v31 正是靠第三次复跑拿到了新读数（构成逐字相同 ＋ 三家分属三个行业，全部是"提及当事公司"而非"当事公司自己申报"）。**v32 把用法定死为三组并列**：`forms=S-1` 得到可复现的窄序列（每次 5 条）；缩短期间做当日／次日核对；`root_forms=S-1` 会带出全部含注册声明系的表单（8-K／NPORT-P／485 系列，实测 195 条）。**窄序列之外的命中必须逐条看表单类型——v32 正是从第二组的 8-K 里追到一条带实质内容的一手读数（交易对手披露的 116 亿美元付款承诺）。**

38. **同一个 `<section>` 容器里放两段可独立替换的内容时，切片终点会连带删除中间整块（v24 首见、v32 再犯，本项目最贵的一类脚本坑）**：v32 的计划节**没有自己的 `</section>`**，`</ul>` 之后直接接 `<h2>附录 A：版本变更日志</h2>`，两者共用同一个 `<section class="card next-panel">`。用「起点＝计划 h2 → 终点＝其后某处 `</section>`」做 `slice_rep`，一次把附录 A 全部 48.6k 字符静默删掉，而 **div 逐块平衡、`<span>` 计数、`<b>` 栈式＋净变化、禁用括号、版本同步 17 处全部照样通过**。**唯一能在落盘后立刻查出的是：落盘后立刻 `print` h2 列表 + 文件总长度，并与上一版逐行比对**（本次靠长度由约 601k 骤降到 547,768 且 h2 少两条发现）。**做法：① 切片前先 `print(re.findall(r'<h2[^>]*>(.{0,40})', s))` 数清两版 h2 条数与位置，确认起点与终点之间**只有**要替换的那一块；② 若共用容器，终点必须取"下一块的起点 h2"而不是 `</section>`；③ 修复方式是从上一版原文件取回被删整块并在其内部插新条目，**不得重跑原段脚本**；④ 把这处缺陷如实写进附录 A 日志（本项目把它当作正文素材而非隐疾）。

39. **`ins_before` 的载荷里不要再写一遍锚点本身（v32 实例）**：v32b 把增量段末尾也写成 `<div class="timeline">`，而 `ins_before` 的锚点也正是 `<div class="timeline">`，结果 HTML 里出现两个连续的 `<div class="timeline">`（div 逐块该节 +1，其余校验全过）。**规范：载荷只写内容，锚点标签由 `ins_before` 自己保留；载荷末行不要复制锚点。**

40. **`slice_rep` 的终点串会被原样写回，是 `#28`／`#29` 的同一族盲区的第三形态（v33 实例）**：v33a 用 `slice_rep('<div class="ver-banner">', '<span class="v-pill">v31 → v32</span></div>', VB)` 换 banner，其中 VB 只写到 `</span>`（缺最外层 `<span>` 的闭合），而终点串被原样写回，于是落盘后同时出现两个缺陷——**`<span>` 计数 650 vs 649（开多一个）＋ 本版配对的旧药丸 `v31 → v32` 残留**。**而 `div` 逐块平衡（10 节全过）、`<b>` 栈式＋净变化、禁用括号、版本同步 17 处全部照样通过**——只有「`<span>` 计数」与「旧版本串残留扫描」两项分别能查到一半。**做法：① 换 banner／meta 药丸时，`new_middle` 的标签必须与起点标记**成对闭合到同一层**，写完后立刻在脚本内 `print(s.count('<span'), s.count('</span>'))`；② 自检脚本除计数外，再对上一版的**版本串**（`v{N-1} → v{N}`／`v{N-1}`）做一次残留扫描，命中即判未替换干净；③ 发现后**不得重跑 v33a**（重入会二次插入），另写 `_build_v33g.py` 只做「旧串 → 新串」一处精确替换，并在同一句里同时补上缺失的 `</span>`。**推广：`<div>`、`<b>`、`<span>` 之后，把「上一版版本串残留」列为第四种必查项——它是唯一能同时暴露"终点串写回"与"药丸漏改"的信号。**

42. **【最重要的一条新纪律·v36 首见】写批判点之前必须先对上一版做「候选事实逐个 grep 去重」，否则会把已登记内容当新增（v36 实测 5 条候选里 4 条是旧的）**：项目到 v35 时已累积 147 条批判点与逐版厚骨架，绝大多数"看起来很新"的二手事实其实早已登记。v36 初稿曾把以下四条误当新增——① Anthropic Q2 财务两口径（营收 109 亿 vs 115 亿、营业利润 5.59 亿、算力成本比 71→56 美分）→ **v35 骨架第 ⑮ 条已登记**；② 一位具名投资人把投资下限放在约 1 万亿美元并称会远低于市场预期出清 → **v34 的 141 已登记（且当时未点名）**；③ 供应商注册声明里上限约 446 亿美元／融资前提／退出权 → **136 已登记**；④ "模型主导该公司 26% 的模型研发"→ **v28 的 103 已登记**。另两条也已被登记：某法案以 417 比 3 通过、Amazon 约 21%／Alphabet 约 15% 持股。**正解（本版实跑有效的流程）：① 先用十几个关键词／完整数字串（含千分位与小数）对上一版 HTML 跑一遍 `grep -c`，命中数 >0 即降级；② 命中的一律改写为「本条是 XXXX 的补全／本条为漏登补齐（标明真实发生时间）」，并在同一段写明理由与"不重计增量"；③ 只有 grep 命中为 0 的才写进「增量事实」段落与新增批判点；④ 把"初稿误列 → grep 查出 → 如实降级并改写横幅计数"的过程写进正文，比静默修正更有价值。** 这条纪律的推论：当项目进入后期，**新增批判点的正确来源不再是"再检索一次"，而是"换一个维度去看已有的东西"**——v36 之所以拿到六条真正新的，靠的是换核对单位（关键词→实体名）、换观察层次（对外口径 vs 审计数字）、换栏位（民调 vs 资金）、换通道（州行政 vs 州立法），而不是再跑一遍相同的搜索。

43. **EDGAR 全文本检索端点可换「核对单位」，实体名与关键词是两个不同的单位（v36 首次实跑）**：`https://efts.sec.gov/LATEST/search-index` 除 `q=`＋`forms=`／`root_forms=`＋`startdt`／`enddt` 之外，把 `q=` 换成带引号的实体全名（如 `q=%22Anthropic%20PBC%22`）即从"关键词单位"切到"实体名单位"，用于核对"以该公司为**申报主体**（而不是提及对象）的表单是否存在"。v36 实测两单位结果：关键词单位（09-01~09-27、注册声明系）5 条、构成与第三至第七次逐字相同；实体名单位（09-01~09-28）123 条、**前列全部是基金持仓表 NPORT-P**。**记账纪律：换单位产生的新读数与换期间产生的新读数必须分列；同一参数复跑而构成不变时只记基线并如实写"本次复跑的新增信息量为零"；四个核对单位（关键词／实体名／表单类型／承销团名单）的命中数不得相加。**

44. **「单位陷阱」值得独立成条，而不是只当一句纪律（v36 的 150）**：当同一个数字在不同来源出现量级差异（v36 实测：可寻址市场"约 3 万亿美元"与"逾 30 万亿美元"），正确做法不是"两说并列"一笔带过，而是**单开一条批判点**，并据此立下可执行的记账规则——**凡引用倍数（估值／收入、估值／运行率），必须同时写出分子与分母的口径来源；若两者来自不同量级的口径，则该倍数无效、不得引用。** 同时须并列一条独立的批评口径（v36：一位估值学者称这类数字"已达到可信的边界并在向外推"，英文原文 reaching the end of what's plausible and pushing beyond），并写明它只作观察项。

41. **换 banner／meta 药丸一律用 `cut_rep`（两端都不写回），不要用 `slice_rep(keep_end=True)`（v35 验证有效，从根上消掉 #28／#29／#40 那一族）**：`cut_rep(s, start_mark, end_mark, new_full, tag)` 把 **[start_mark, end_mark] 整段（含两端）**替换为 `new_full`，不写回任何端点串。做法：起点取 `<div class="ver-banner">`、终点取它之后第一个 `</div>\n\n<section class="card" style="border-color:#7c3aed;border-left:4px solid #7c3aed">`（或 meta 的 `</div>\n</header>`），`new_full` 自带完整的 banner／meta 与后随部分。**这样既不会像 v28 那样把旧版本号留在 banner 里，也不会像 v33 那样因终点串写回而同时出现「旧版本串残留 ＋ `<span>` 开多一个」。** 用完后仍要跑一次「上一版版本串残留」扫描（`v{N-1} → v{N}`、`v{N-1} · `、`{N-1} 个批判点` 等），但要注意：**若扫描放在后续替换之前，命中的可能正是还没轮到改的那几处（v35 实测 banner 换完后 meta 与第三节 h2 仍含旧串，扫描报 2 处 RESIDUAL-WARN，随后被 meta／h2 替换消掉）——因此残留扫描必须在全部替换完成之后（`_check_v{n}.py` 内）再跑一次，构建期中途的命中只能当提示、不能当失败。**

45. **锚点里含标签前缀时，`new` 串必须以同一标签开头，否则整段开标签被静默吞掉（v37 实例，`#40` 的同胞第四形态）**：v37d 用 `rep(s, '<p class="lead" style="color:#7c3aed;font-size:13px"><b>v36 的概率位移', S5, …)` 替换第五、七节的导语，**锚点带了 `<p class="lead" …>` 前缀，而替换串 `S5` 只从 `<b>` 开始**——于是两处 `<p class="lead">` 开标签被替换掉、只剩 `</p>`，形成"少两个开标签"的失衡。**该缺陷能骗过全部四类计数闸门**：`div` 逐块平衡、`<span>` 计数、`<b>` 栈式＋净变化、禁用括号与版本同步**全部照样通过**；`p` 的净计数也没被拦住，因为 **v36 基线本身 p 开合差就是 3（历史遗留未闭合 `<p>`），而 v37 的差仍是 3**——"差值等于基线"反而掩盖了"这一版少了两对"。**做法：① 写锚点时把被吃掉的标签一并写进 new 串的首部（`S5` 必须以 `<p class="lead" …>` 开头）；② 自检脚本对 `p` 必须用「基线比对」而不是「绝对平衡」：断言 `(open_new - open_old) == (close_new - close_old)` 且 `(open_new - close_new) == (open_old - close_old)`，两项都要过；③ 更省事的是**永远让锚点从块级标签之后开始**（起点取 `</h2>` 或 `\n<p` 之后的纯文本），**不要把 `<p …>`／`<div …>` 这类开标签写进锚点头部**；④ 发现后按铁律**不重跑 v37d**，另写 `_build_v37f.py` 用「旧串→新串」加回缺失的开标签，并在同一次运行里把 `p` 的净变化对基线复算一遍确认归位。**推广：`<div>`（#32）、`<span>`（#29）、`<b>`（#32）之后，`<p>` 是第四个"计数可用但会被基线差值掩盖"的标签族。**


46. **正文里把标签名写成字面尖括号会污染四个标签族的计数（v38 实例，全新一类）**：v38 计划节的自我约束条目里写了 `<div>`／`<b>`／`<span>`／`<p>` 四个被反引号包裹的字符串，落盘后文件计数变成 div 423/422、span 738/737、p 1019/1015 ——**逐块 div 平衡、`<b>` 栈净变化、版本同步 18 处、禁用括号全部照样通过**，只有对**全文件做栈式扫描**并打印「残留下标 + 上下文」才定位到落点是这三个字符串。**规范：正文、附录与自检条目中提到标签名时一律用中文描述（块级容器／加粗／行内容器／段落），不写尖括号字面量。**推论：`_check_v{n}.py` 里除四类计数外，应把「正文是否含被反引号包裹的标签名」列为一条独立断言。

47. **`cut_rep` 换 meta 长药丸时，`new_full` 末尾多写一个 `</span>` 只被 `<span>` 计数拦住（v38 实例，`#29`／`#40` 同族第五形态）**：v38a2 用 `cut_rep` 把 meta 区两颗长药丸整段重写，`new_full` 里对 <机构> 那颗药丸重复写了一个前置 `</span>`，落盘后 `<span>` 计数 719/720；而同一次 div 逐块平衡、`<b>` 栈净变化、禁用括号、版本同步与 p 差值**全部照样通过**。**做法：① 用 `cut_rep` 拼装多颗药丸时，先数清「被删除区间内原有几对标签、`new_full` 里有几对」，两者必须相等，并在脚本内 `print(s.count('<span'), s.count('</span>'))`；② 发现后按铁律不重跑原脚本，另写 `_build_v{n}a3.py` 用「旧串→新串」删掉多余的一个闭合；③ `<span>` 计数是继 `<div>`（#32）、`<b>`（#32）、`<p>`（#45）之后第四个「唯一能查出一类缺陷」的计数闸门。**

48. **「一手检索换动作」的三分法（v38 首次执行，可直接复用）**：注册声明系核对到后期，可产生信息增量的动作只有三类，且读数必须分列——① **换单位**（关键词 → 发行人实体全称）：本版实测 5 条 → 2 条，发行人不变，只排除「参数选得窄」；② **换期间**（把 enddt 收到最近三天）：v38 正是靠这一步拿到全窗口唯一的新读数（一家以当事公司命名的专项基金载体提交的法案 D）；③ **换表单类型／换载体**（root_forms 放宽到全部含注册声明系，或改查法案 D）：用于捕捉「不是它自己申报、也不是交易对手申报」的第三方载体。**纪律：同参数复跑只记基线并如实写「新增信息量为零」；三个动作的读数不得相加；四个核对单位的命中数不得相加。** 端点与参数写法见 #37／#43。

49. **上一版「计划节」里写的「第一次／唯一」断言不可直接继承，必须先去重（v39 实例，`#42` 的反向形态）**：`#42` 防的是「把上一版正文里已有的东西当新增」，本条防的是「把上一版**计划里**打算做的东西当已经做成」。v38 计划节写「下一版第一次并列保留挂牌延后口径」，而该口径其实**已在 v38 正文登记**；v39 初稿照抄这句，把「可能延后至 11 月中期选举之后」误写成「第一次出现并并列保留」，直到落盘后对该串 grep 才查出，另写 `_build_v39a2.py` 定向更正为「上一版已登记、本版只更新余额、不重计为新口径」。**规范：写任何「第一次／唯一／首次」之前，必须用该事实的关键词＋完整数字串对**上一版全文**`grep -c`，命中 >0 即降级为「补全」或「已登记、不重计」并在同段写明理由；**计划节的内容不能当作事实来源**，它只是「打算去核的方向」。附带纪律：**构建脚本若在任何替换之前崩溃（如列表解包 `ValueError`），文件保持 `cp` 基态、无需回滚，改好重跑即可**——崩溃早于 `report()` 落盘即天然安全；但若崩溃发生在 `report()` 之后（多段脚本），必须按 `#31` 走「不重跑、只读回校验」。

50. **自检脚本里的「同步断言串」必须从待检文件实测复制，不得凭上一版脚本的结构推断（v41 实例，最容易假报的一类）**：`_check_v40.py` 把六条情景标题写成 `'· v39 21% → v40 20%'` 这种带 `· ` 前缀的统一形态；v41 照抄结构、把断言写成 `'· v40 53% → v41 54%'`，于是**六条里有五条假报「情景标题未同步」**——而正文其实全部正确，唯一的原因是**只有情景 1 带 `· ` 前缀（「（基准情景 · v40 20% → v41 21%）」），情景 2–6 不带**。（场景标题前缀）**做法：① 写任何同步断言前，先从待检文件里 `print(repr(s[i:i+80]))` 把六个标题原样打出、再粘进 SYNC 列表；② 断言失败时先怀疑断言串本身，不得直接去改正文；③ 改断言后必须重跑一次确认 FAILS 清空，并把这次的「假报警」原样记进当版 memory（比静默修正有价值）。
51. **`_iter_meta.json` 的 `history` 会与 `v{n}_zh` / `iteration_meta.latest` 不同步（v41 发现 v40 整条缺项）**：v40 那一版把 `latest_version`、`v40_zh`、`iteration_meta.latest` 都更新了，**唯独 `history` 没有追加 v40**（history 末项仍是 v39）；因为三者分属不同的写入步骤，任一步中断都会留下这种「半更新」状态，而前几次自检只断言了 `history` 长度递增、没有断言**末项版本号**。**规范：① 每版 meta 写入后必须断言 `d['history'][-1]['v'] == 'v{n}'` 与 `d['history'][-2]['v'] == 'v{n-1}'`（不能只断言长度）；② 发现缺项时按「补登」处理——用 `v{n-1}_zh` 与 `iteration_meta.latest` 还原该条，`annotation` 写明「补登项，不重算」，并在顶层 `meta_open_facts` 里留下一条记录；③ 补登不得改动既有正文或重算历史数值。**
52. **向项目 memory / 技能文件追加文本时，不要用 Bash 内联 Python 或 heredoc（反引号被 shell 当命令替换吞字）**：v41 用 `python -c \"...\"` 追加自动化 memory，正文里含一对反引号包裹的示例串，`bash` 把两个反引号之间的内容当命令执行 → 报 `·: command not found`，且**落盘后的文字里该处直接缺字**（退出码仍为 0，不报错）。这正是失败教训库 `#120`（shell 反引号命令替换吞字符）在项目流里的再现。**规范：凡要写入的正文含反引号、`$`、`!` 等 shell 元字符，一律改用 Write / Edit 工具落盘；写完必须回读一次并 grep 关键片段确认无缺字。** 附带：遍历 `history` 取版本号时不能只用 `d['v']`——历史遗留的 v28 条目键名是 `v_min`，应写成 `x.get('v') or x.get('v_min')`。

53. **`_iter_meta.json` 写后按「全角括号」做**全文**禁用字符断言 → 必然失败（v43 实例）**：该文件的 42 个历史条目本身就含全角括号（`截至 vXX（…）：` 是 `cumulative_judgment` 这一字段的**既有体例**，每版沿用），因此 `assert bad not in txt` 只要是扫全文就永远不通过。v43 因此在**文件已落盘之后**触发该断言——按 `#31`／`#49` 的「断言失败不得重跑」（重跑会二次追加并覆盖真实备份），只能改为**只读回校验**：断言 `len(d['history']) == n_hist + 1`、`len(d.keys()) == n_keys + 1`、`history[-1]` 与 `history[-2]` 的版本号、`v{n}_zh` 的关键字段、以及 `v{n}_zh` 与 `cumulative_judgment` **两者**内的禁用字符计数。**规范：禁用字符断言必须把作用域收窄到「本次新增的那几个键」，不得扫全文；备份 sha256 必须在 `copy2` 之后立刻打印留档。**

54. **附录 B 的版本条目是「由新到旧」陈列，新版条目必须插在**上一版条目之前**（v43 实例）**：v28 起每版都把自己那一条插到附录 B 的首位（v40/v41 的实测顺序均为 `v41, v40, v39, …`），**唯独 v42 把自身条目 `append` 到了附录最末尾**，于是 v43 若照「插在首位」的习惯操作，会得到 `v43, v41, v40, …, v24, v42` 这种「v42 孤悬末尾」的错序。**做法：① 每版把上一版（若位置错误）与本版两条一并归位为 `v{n}, v{n-1}, v{n-2}, …` 的降序；② 自检加断言 `find(v{n}) < find(v{n-1}) < find(v{n-2})` 且三条各恰好一次；③ 此类纯陈列顺序的整理要在附录 A 里如实记一句「只涉及陈列顺序，不涉及事实、口径与区间」，不要静默修正；④ 移动整条 `<p>` 块时用「切片 + 重定位插入」，切片端点取 `<p><b>v{n} 新增来源与口径说明` 与紧随其后的 `</p>`，并在重定位后重新 `find` 两个标记，不得复用移除前的下标。**

55. **「演化概览」每版**整节重写**，而「子桌面 h3 导语」是自 v28 起的**冻结块**（v43 实例，两种处理必须分清）**：① 演化概览那一节（`<h2>v{n-1} → v{n} 演化概览（增/强/弱/纠）</h2>` + 四个 metric + 结构判断长段）**每版整节替换**，h2 里的版本对、批判点数对、支持／反驳净变化数字、区间与情景行、以及「v{n-1} 的结构性判断是……；v{n} 要往前走的半步是……」都要重写；② 而 `<h3>支持论据 vs 反驳论据：NNN 张子桌面</h3>` 底下的导语段落**从 v28 起就没有再重写过**（每版只在段首追加一句、其余历史块原样保留），因此**每版只需把 h3 里的数字改掉**（v40→141、v41→147、v42→153、v43→159，每版 +6），**不要去重写那段导语**——重写会破坏「跨版可比」这一设计意图。③ 另须记住：**演化概览与第一节共用同一张 `<section class="card">`，该卡片内并没有独立的 `</section>` 收尾**，所以这一节只能用「起点 = 演化概览 h2、终点 = 第一节 h2」切片（`slice_rep`），`new_full` 内**不得再写一遍终点 h2**。
