## 构建流程（v14 起固定，**禁止单次 Write 长 HTML**）

```bash
cp v{n-1}_*.html v{n}_YYYY-MM-DD_HH-MM.html
# 然后写 _build_v{n}a.py ... f.py，每个脚本用 rep(old,new,tag) 且 assert s.count(old)==1
```

稳健要点：
- 每次替换前 `assert s.count(old)==1`，替换后打印失败清单；用绝对路径。
- **插到区块末尾**用 `ins_before_next_heading()`：取「下一个 `h2/h3/h4` 或 `</section>` 的最小下标」当插入点。结构等价且不需要数闭合标签，天然避开 prefix 丢失坑。
- 全角引号按文件实际字符写，锚点含引号时先 `repr()` 打印实际字符串。
- 表格行的演化单元格 span 不统一（`delta-up` / 内联 `style`），写长行锚点前先打印该行原文。
- 禁止 shell 的 sed/awk 改 HTML。
- **计划节与附录 A 共用同一 `<section>`（v24 首见、v32 再犯）——最稳的安全做法（v34 验证有效、未复发）**：计划节的整段替换**不要**用 `</section>` 作终点，改用**两个各自唯一的标题当切片端点**——起点 `<h2>v{n-1} 计划（下一版 ≤ …）</h2>`（唯一）、终点 `<h2>附录 A：版本变更日志</h2>`（唯一），两端点都落在同一 section 内部，天然不会连带删掉后面的整块。**并且在 f 段落盘后立刻打印全文件 h2 列表 + 字符总长与上一版逐条比对**——这是唯一能在落盘后立刻发现「整块被删」的手段（v32 靠长度由约 601k 骤降到 547,768 与 h2 少两条才发现）。
