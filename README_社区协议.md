# Skill 社区 · 共享协议 v1

## 一句话

**社区共享的最小单位是「知识条目」（SKILL.md 的一个章节），不是整个 skill 文件。
共享与否由作者逐条目决定，默认不共享。**

## 为什么要做到条目级

实测本机 121 个自建 skill，其中 **67 个含隐私特征**（本机用户名 41%、D 盘路径 40%、
机构实名 19%、真实邮箱 4%），只有 54 个整份干净。

若按整文件共享：多数贡献者被迫公开本机路径与所属机构。
若让每人手动挑文件：粒度仍然太粗——一个 SKILL.md 里常同时有可公开的方法论
与不可公开的内部绑定。

按章节切分后：**5503 个条目里5231 个干净（95%）**，隐私只集中在 272 个条目上。
典型案例 `ai-reg-ipo-compat-iterate`：13 个条目里仅 2 个含路径与内部 ID
（都在 frontmatter 与「何时使用」里），**其余 11 条方法论完全可共享**，
包括「五十五条脚本坑」这类最有复用价值的部分。

结论：粒度下沉到条目，让贡献者可以只贡献方法论、只留下私有绑定。

## 三层目录与共享边界

| 目录 | 内容 | 进git | 谁可见 |
|---|---|---|---|
| `_private/` | 条目原文（含本机绑定） | **否** | 仅作者本机 |
| `_staging/` | 待发布的脱敏条目 | **否** | 仅作者本机 |
| `registry/` | 已授权发布的条目 | **是** | 全体社区成员 |

**「不共享」的实现方式是「不在 `_staging` 里」，不是某个 permission 字段。**

这是本方案最重要的一条。标记式授权会被任何聚合脚本绕过——
只要下游有人读全目录再筛选，「标记为不共享」就等于没标记。
目录级隔离是结构保证，标记只是君子协定。

`.gitattributes` 里已把 `_private/` 与 `_staging/` 声明为永不进版本库，
即使有人手工 `git add .` 也进不去。

## 作者的三种选择

```
默认         原文含本机绑定的条目自动留在 _private，不发布
显式共享     零隐私条目的方法论，默认发布进 registry
显式不共享   任何条目都可不发布：它只留在 _staging，不进 registry
```

作者拥有最终否决权：**任何条目都可以不发**。
社区的价值建立在「大家愿意分享」之上，不强迫。

## 发布前的三重闸门

一重比一重独立，前一重过了不代表后一过：

1. **原文绑定检测**：条目原文含本机路径 / 内部 ID / 机构名 → 默认私有。
   判定基于**原文**而非脱敏后——因为脱敏会把「非X那一颗药丸」洗成
   「<机构>那一颗药丸」，语义直接断掉。脱敏是保险，不是判据。
2. **脱敏后复验**：占位符密度超过 2% 即判语义已损，不予发布。
   这条能拦住「洗得太干净导致读不成句」的条目。
3. **发布前裸形态终检**：用**独立于脱敏规则的另一套检查表**再扫一遍。
   复验若复用替换用的同一套正则，会一起错——这是本轮实测的真实教训
   （详见下）。

## 四条已踩过的坑

### 坑 1 · 脱敏规则漏掉否定前缀形态
`华源证券 → <机构>` 规则漏掉了「非华源」这种形态，
两处 `非华源那一颗药丸` 直接进了 registry。
**正解**：长模式优先，且必须显式列出否定形态（`非华源`、`非华源证券`）。
写这条纪律的人在写规则时也漏了它——**规则表里举例必须用占位符而非真值**。

### 坑 2 · 「脱敏后干净」被误当成「可以共享」
首版 stage 报「13 个条目全部可共享」，而 scan 明确报2 个含隐私。
根因：stage 只看脱敏后是否干净。
**修正**：授权判定必须基于**原文**，脱敏只是第二道保险。
这条直接对应用户诉求「有的人他不愿意共享」——
不共享必须是默认值，而不是需要额外标记的例外。

### 坑 3 · 私有条目落进 staging 后，publish 会把它全发出去
改完 stage 后重跑，publish 仍发布 13 条（应11 条）。
根因：publish 直接读 `_staging`，而私有条目也被写进了 staging。
**正解**：私有条目**根本不写 staging**。staging 只装待发布条目，
publish 于是无需再判断。「不共享」的保证从「判据」升级为「文件不存在」。

### 坑 4 · 复验正则不能与替换正则同源
若复验复用 `SCRUB_RULES`，两者会一起放过同一批漏网项。
**正解**：publish 用独立的 `BARE` 检查表（裸形态：机构名/用户名/内部ID/裸路径/wxid/邮箱），
且发布后再扫一遍 registry 产物本身，不信任 staging。
最终以**完全独立的第三方脚本**复核，不 import community.py 任何代码。

## 加入方式

```
git clone <社区仓地址> D:\Skill社区
cd D:\Skill社区
python _工具\community.py scan              # 盘点可共享条目
python _工具\community.py stage<skill名>    # 条目级抽取 + 双重判定
python _工具\community.py publish <skill名> # 过终检后进registry
```

拉取别人的改进：直接 `git pull`，registry 下的条目即为社区共享面。
合并进自己本地的 skill 时注意：**社区条目是方法论骨架，本地项目实例仍属私有**。

## 三条硬规矩

1. **默认不共享**。不确定就留在 `_private`，永远可以事后补发，但发出去很难收回。
2. **原文判定授权**。含本机绑定的条目即使脱敏后干净，也默认不发——
   泛化价值低且语义受损。
3. **registry 之外的一切不进版本库**。工具脚本、私有原文、暂存区都在保护范围内。
